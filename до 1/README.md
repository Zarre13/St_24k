# Практика: библиотека, Kanban и бронирования

SQL-файлы рассчитаны на PostgreSQL и выполняются в pgAdmin по порядку:

1. `database/01_library.sql` — каталог книг, связи книг с авторами и жанрами.
2. `database/02_kanban.sql` — пользователи, доски и задачи, индексы, soft delete, триггер и представление.
3. `database/03_bookings.sql` — временные интервалы с защитой от пересечений и процедура истечения бронирований.

Ключевые правила для API:

- Книга возвращается вместе с автором и жанрами; список можно фильтровать по жанру и году. При удалении автора книги сохраняются благодаря `ON DELETE SET NULL`.
- Пароли пользователей Kanban хранятся только в виде bcrypt/Argon2-хеша. Все операции с досками и задачами должны проверять доступ пользователя к доске. Списки задач исключают `is_deleted = true`; допустимые поля сортировки нужно ограничивать белым списком.
- Время бронирований передаётся в ISO 8601 с часовым поясом и сохраняется как `TIMESTAMPTZ`. Нарушение ограничения `bookings_no_confirmed_overlap` имеет код PostgreSQL `23P01` и преобразуется API в HTTP 409.

После установки схемы процедуру завершения просроченных бронирований можно запускать командой `CALL booking.cancel_expired_bookings();`.
